# 消费金融自动化 ETL 与对账数据流水线 (Production-Level ETL Pipeline)

## 项目概述
本项目包含用于持牌消费金融机构生产环境的核心自动化脚本。主要用于解决多数据源割裂、跨库对账复杂以及风控日报生成效率低下的痛点。

该数据流水线作为风控管理报表的核心引擎，负责从多个异构数据库（MySQL、PostgreSQL，以及历史 Oracle 节点）提取原始数据，每日自动清洗、校验并聚合上万条授信与支用流水明细，在保证绝对数据一致性的前提下，实现高度自动化的报表产出。

## 核心解决的技术挑战

* **跨数据库统筹调度：** 利用 Python 的 `contextmanager` 设计了统一的数据库连接工厂，安全、高效地管理 PostgreSQL 与 MySQL 的并发连接池。
* **堡垒机受限环境修补：** 成功攻克了高安全级别堡垒机内底层环境陈旧的问题。通过动态运行时补丁（Runtime Patching），解决了旧版本 `openpyxl` 与新版本 `numpy`/`pandas` 之间的数据类型调用冲突。
* **复杂 SQL 逻辑转换与优化：** 将冗长复杂的 Oracle 特有语法（如外连接、特定日期格式化）重构为高度优化的 PostgreSQL 语法。支持基于多层级客户画像（如风险定价分层、目标白名单客群）的动态 SQL 过滤与多维聚合。
* **金融级零容错保证：** 核心指标计算直接挂钩内部高风险决策与高达 26 亿规模的资产表现。代码通过多重状态双向校验（如 MySQL 与 PG 双边状态对账），确保最终输出的金额与转化率数据 100% 准确。
* **动态报表自适应渲染：** 脚本集成了自动生成多 Sheet Excel 报表的功能，支持动态列宽计算、自适应百分比格式化渲染，彻底剥离了人工干预。

## 技术栈
* **语言:** Python 3.x
* **数据处理与科学计算:** `pandas`, `numpy`
* **数据库驱动:** `psycopg2` (PostgreSQL), `pymysql` (MySQL)
* **报表工程:** `openpyxl`
